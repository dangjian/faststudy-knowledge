# kg-query — 知识点查询（LLM 前置）

## 何时用
- 用户问「XX 概念是什么 / 怎么学 / 和 YY 什么关系 / 先修有哪些」。
- 需要从图谱精准定位概念、章节、关系并组织自然语言答案。

## 核心原则
**不读 `dist/`、不全量加载图谱**。图谱是层级网状，LLM 逐层下钻，每次只读命中路径上的 YAML 切片。
脚本（`kg_ask.ts`）只做两件 LLM 不擅长的事：① 跨大关系文件的精确切片；② 先修链的多跳传递闭包。

## 查询流程（严格顺序）

> **第 0 步(必做)**:先读 `knowledge/graph/index.md`(问句→路径映射 + ID 前缀速查 + 局限声明),按表定位再下钻;严禁跳过直接全库 grep。

### Step 1 — 定位教材（Textbook）
- 先按目录树定位 `knowledge/content/<年级>/<学期>/<科目>/<textbookId>/index.md`，读其 front-matter 的 `chapters` 键锁定 `textbookId`
  （如 `BSDU-7-1-Math`；分层 v3 后 structure 由书级 index.md front-matter 派生，`graph/entities/structure/` 已不存在）。不确定时把候选列出请用户确认。
- 也可用：`pnpm kg:ask tree <textbookId>`（knowledge 根目录）直接拿章/节树；每个节带 `p.起-止` 页码，可据此估算篇幅。

### Step 2 — 下钻到 Section
- 从教材 YAML 或 `tree` 输出拿到 Chapter / Section 列表，锁定目标 `sectionId`
  （如 `BSDU-7-1-Math-C1-S1`）。
- 拿该节概念：`pnpm kg:ask concepts <sectionId>`（knowledge 根目录）。

### Step 3 — 读 Concept 切片并语义匹配
- 用 Step 2 拿到的 `concept:<学科>:<名称>` id，去 `knowledge/graph/entities/concepts/<学科>.yaml`
  （每学科一个聚合文件，顶层为实体数组）内按 id 查找。
- 聚合文件较大且含全学科概念；只取目标概念条目，不要全量读入上下文（可 grep 定位）。
- 若用户用自然语言描述（非精确名），在 `concepts` 结果与同节/同章概念里做 **语义匹配**，选最贴合者；
  候选>1 时列出并请用户确认，不默默假设。

### Step 4 — 沿关系边推理（按需调 kg_ask）
- 先修链（跨年级，多跳）：`pnpm kg:ask prereq <conceptId>`（算法闭包，必用脚本）。
- 覆盖该概念的节：`covered <conceptId>`（可能跨章/跨年级，说明概念复现位置）。
  输出末列 `p.起-止` 是教材页码，**回答里引用位置时用它**（如「教材第 29–37 页」），
  不要自己编页码；没有 `p.` 列说明该实体无页范围（概念/词条通常没有）。
- 相关概念：`related <conceptId>`；组成部分：`partof <conceptId>`（整体-部分层级）。
- 例证学习项：`demo <conceptId>`（词/句/汉字）。
- 解题模型：正文直接读目标节 md 的 `## 解题模型` 区块。

### Step 5 — 组织答案
- 用读到的切片 + 关系边，生成自然语言答案。结构建议：定义 → 关键属性 → 先修（若有）→ 相关/易混（若有）→ 例题/图示（若有）→ 所在章节路径。
- 答案必须基于图谱事实；**不要编造**图谱里没有的关系。若某关系缺失（如 `part_of` 为空），明说「图谱暂无记录」。

## 判断「学到什么程度算会」

概念上的 `masteryCriteria` 是**错误规避式**标准（形如「能指出并纠正这一错误：…」，
全库 13,566 条均由易错点反推，抽检 29/30 通过）。它回答的是「学生是否踩了这个坑」，
**不是**「学生能不能做到」。

所以判断掌握度时按两步：

1. **先查已有标准**：`kg_concept` 返回的 `masteryCriteria`，逐条问「这条做到了吗」
2. **再现场补一条正向标准**：从该概念所在节的正文（`kg_section` 的 text）里，提炼出
   「学生要能做出什么具体动作」——例如学完「配方法」，正向标准是「能独立把
   x²+6x+5=0 配成 (x+3)²=4 并写出两根」，而不是「知道配方法的步骤」

**不要用套话**：「能说出X的关键要素并举例」这类换任何概念都成立，实测判读通过率仅
33%（30 条抽样），对判断掌握没有区分度。

**不要假设全库都有正向标准**：目前只有错误规避式。缺正向标准时如实说明「图谱只提供
易错点维度的判定，正向能力建议由教师或结合正文确认」。

## 解题模型

- 解题模型正文（方法步骤/易错点/动画/视频外链）在章节 md 的 `## 解题模型` 区块内，按概念 `covered_by` 定位节后直读。
- 注意：并非每节都有 `## 解题模型` 区块；没有时如实说明「该节暂无解题模型」，严禁编造。

## 反模式（禁止）
- ❌ 读 `knowledge/dist/graph.json` 全量进上下文。
- ❌ 为找先修手写多跳 BFS（用 `prereq` 脚本）。
- ❌ 全量读 `related.yaml`/`demonstrates.yaml` 等大关系文件（用 `related`/`demo` 等切片）。
- ❌ 在不确定概念时默默选一个；候选多就问。

## 边界
- 查不到：先确认教材/学科/年级是否已在图谱（见 INDEX §3 实体 id 格式）；若确属内容缺口，
  回报「该主题尚未录入图谱」并建议走 `kg-ingest`。
- 本 skill 只查询，不写入图谱。

## 硬边界(消费型约束)

- **只读零副作用**:不改图谱/content/任何文件,不产生 git 变更;发现数据问题→记录并建议走 kg-edit,不顺手修
- **诚实性**:图谱没有的知识点就是没有——必须如实回答"图谱未覆盖",严禁编造;回答只用图谱与章节 md 原文中存在的内容
- **预算**:**关系边推理**最多 3 跳(结构下钻 Textbook→Chapter→Section 与脚本闭包如 `kg:ask prereq` 不计入),单轮最多读 5 个数据文件(`kg:ask` 切片调用不计入);批量任务口径以 `tools/kg/skills/00-META.md` §2 预算铁律为准
- **溯源**:结论附来源(节 id / 概念 id / sourceRef),让用户可回查
